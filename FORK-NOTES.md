# Что добавлено в этом форке

Основа — [uisato/ableton-mcp-extended](https://github.com/uisato/ableton-mcp-extended),
который сам является форком [ahujasid/ableton-mcp](https://github.com/ahujasid/ableton-mcp).

Оба проекта хороши в **создании** музыки и слабы в **наблюдении** за ней.
Здесь закрыты дыры, на которые натыкаешься в реальной работе.

| | Было | Стало |
|---|---|---|
| Команд Remote Script | 46 | **68** |
| Инструментов MCP | 46 | **71** |

---

## Чтение и правка MIDI

В `extended` не было **никакой** возможности прочитать ноты: сервер умел только
писать. Это значит, что с любым материалом, написанным не в текущей сессии,
приходилось работать вслепую.

| Инструмент | Что делает |
|---|---|
| `get_clip_notes` | читает ноты клипа: высота, позиция, длительность, велосити, а также MPE-выражение и probability, если они есть |
| `clear_notes_from_clip` | очищает клип, не удаляя его |
| `replace_notes_in_clip` | clear + add одним вызовом — настоящая перезапись клипа |
| `delete_clip` | удаляет клип из слота session view |

Чтение нот и очистка портированы из `ahujasid`, где они появились позже
ответвления `extended`. `replace_notes_in_clip` — свой: `add_notes_to_clip`
только дописывает, поэтому замена содержимого требовала двух шагов.

## Микшер

`extended` умел только громкость и панораму.

| Инструмент | Что делает |
|---|---|
| `set_track_mute` · `set_track_solo` · `set_track_arm` | эти состояния читались в `get_track_info`, но сеттеров не было ни одного |
| `set_send_level` | посылы на возвраты — в исходном коде слово `sends` не встречалось вообще |

Плюс `get_track_info` теперь **видит возвраты** и отдаёт список посылов.
Раньше он ходил только по `song.tracks`, хотя соседние команды громкости уже
умели `song.tracks + song.return_tracks`.

## Сцены

Их не было совсем: слово `scene` не встречалось в коде ни разу. Для работы в
session view это половина смысла — без сцен клипы нельзя запустить строкой.

`get_scenes` · `fire_scene` · `create_scene` · `delete_scene` ·
`duplicate_scene` · `set_scene_property`

`get_scenes` показывает не только имена и состояние, но и **какие клипы лежат
в каждой строке** — то есть что именно запустится.

Запись темпа или размера сцены через API автоматически включает
соответствующий контрол, отдельного флага не требуется
(release notes Live 11.0.5).

## Свойства session-клипов

`Clip` — это один класс: клип в аранжировке и клип в сессии суть один объект.
В `extended` для аранжировки было заведено одиннадцать свойств, а для сессии —
только имя, хотя отличается лишь способ добраться до клипа.

`get_clip_properties` · `set_clip_property`

Четырнадцать свойств — то, что в Live лежит в панели Clip:

```
name · muted (деактивация клипа, клавиша 0) · color
pitch_coarse (Transpose) · pitch_fine (в центах)
looping · loop_start · loop_end · start_marker · end_marker
gain · warping · warp_mode · velocity_amount
```

Читатель молча пропускает неприменимое: у MIDI-клипа не будет `gain` и
`warp_mode`, но вызов не упадёт.

## Wavetable

Самая содержательная часть. Wavetable в Live — это класс `WavetableDevice`,
а не обычный `Device`: у него **71 метод и 30 свойств**, и ни один из них
не виден в списке параметров устройства. Поэтому через обычный
`get_device_parameters` матрица модуляции и выбор волновых таблиц недоступны
в принципе.

| Инструмент | Что делает |
|---|---|
| `get_wavetable_state` | матрица модуляции целиком, волновые таблицы по именам, категории, унисон, роутинг фильтра, полифония |
| `set_wavetable_modulation` | запись в ячейку матрицы |
| `add_wavetable_mod_target` | добавляет параметр как цель модуляции |
| `set_wavetable_property` | выбор волновой таблицы, effect mode, unison mode, filter routing, mono/poly |
| `describe_device_api` | интроспекция **любого** устройства: что реально отдаёт объект в этой сборке Live |

Индексы источников модуляции берутся из живого enum
`Live.WavetableDevice.ModulationSource`, а не из зашитых констант — так
перенумерация между версиями Live ничего не сломает.

`describe_device_api` полезен шире Wavetable: он показывает, что есть у
`SimplerDevice`, `DriftDevice`, `RoarDevice` и других специализированных
классов, документация по которым скудна.

**Важно:** метод `set_modulation_value` отсутствует в документации Live 11,
но существует в Live 12 с сигнатурой
`set_modulation_value(target_index, source, value)`. Проверено интроспекцией
живого объекта на Live 12.4.

## Прочее

`undo` · `redo` — с проверкой `can_undo` / `can_redo`, возвращают
«нечего отменять» вместо исключения.

`create_audio_track` — в `extended` был только `create_midi_track`.

`get_session_snapshot` — всё состояние проекта одним вызовом: дорожки, клипы,
устройства, сцены, возвраты, мастер, cue points. Портировано из `ahujasid`.

## Исправления

**Уход с устаревшего `set_notes`.** Live пишет в лог ошибку
`Clip.set_notes is deprecated since Live 11.0` при каждой записи нот. Обе точки
записи теперь идут через общий `_write_notes`, который пробует
`add_new_notes` с объектами `MidiNoteSpecification` и падает обратно на
старый путь, если сборка Live его не поддерживает. Ответ содержит поле `api`
с именем сработавшего пути.

**Возвраты больше не роняют `get_track_info`.** Live не просто не имеет `arm`
и `clip_slots` у возвратов — он **бросает исключение** при обращении к ним,
поэтому `getattr` со значением по умолчанию не помогает. Обращения обёрнуты.

**`pyproject.toml`** — две правки, без которых проект не собирается:
из списка пакетов убран `AbletonMCP_UDP` (он лежит в другой директории и
является Remote Script, то есть вне Live не импортируется в принципе),
и зафиксирован `mcp[cli]<2` — в MCP SDK 2.0 модуль `mcp.server.fastmcp`
переехал, и сервер перестаёт запускаться.

# Установка

## 1. uv и Python

```
winget install --id astral-sh.uv -e
uv python install 3.12
```

Официальный установщик `irm https://astral.sh/uv/install.ps1 | iex` может не
пройти, если провайдер режет `astral.sh` по SNI — TLS-хендшейк рвётся с
`SEC_E_ILLEGAL_MESSAGE`. winget тянет тот же бинарник с GitHub Releases.

## 2. Зависимости

```
uv venv --python 3.12
uv pip install -e .
```

Extra `xy_controller` ставить не нужно, если не собираешься пользоваться
XY-контроллером: он тянет `pynput`, а это глобальный перехват мыши и
клавиатуры.

## 3. Remote Script

Скопировать `AbletonMCP_Remote_Script/__init__.py` в папку с именем
**ровно `AbletonMCP`**:

```
%USERPROFILE%\Documents\Ableton\User Library\Remote Scripts\AbletonMCP\__init__.py
```

Затем в Live: **Preferences → Link, Tempo & MIDI → Control Surface → AbletonMCP**.

## 4. Регистрация MCP-сервера

```
claude mcp add AbletonMCP -- <путь-к-проекту>/.venv/Scripts/ableton-mcp-extended.exe
```

ElevenLabs-модуль подключать не обязательно: он развязан с основным сервером
полностью и требует своего API-ключа.

# Что нужно знать в работе

**Правки Remote Script требуют полного перезапуска Live.** Переключение
Control Surface на `None` и обратно выгружает и загружает объект, но Python
внутри Live не чистит `sys.modules` — код остаётся прежним. В логе при этом
всё выглядит как успешная перезагрузка, что сбивает с толку.

**Скрипт в папке Live — отдельная копия.** После каждой правки его нужно
копировать заново. Симлинк на репозиторий избавляет от этого, но требует прав
администратора или включённого режима разработчика.

**Первый вызов после старта Live может упасть** с ошибкой вида
`TPyHandle<ASong>` — сет ещё не готов. Повторный вызов проходит.

# Ограничения

Матрица модуляции существует **только у Wavetable** — у Operator, Drift и
прочих её нет в API, там всё живёт в обычных параметрах.

**Параметры VST-плагинов** доступны, только если они выведены в панель Live.
Плагины с более чем 64 параметрами открываются с пустой панелью, и до их
ручек не добраться, пока не добавишь их через Configure Mode в заголовке
устройства. Это ограничение Live, а не MCP.

**У Simpler нет корневой ноты.** Такого параметра не существует — он есть
только в Sampler, где мультисэмплинг и зоны. Чтобы попасть в нужную высоту,
прочитай соседний клип на той же дорожке через `get_clip_notes`.

Не реализованы, но доступны в API и могут быть добавлены: маршрутизация
дорожек, цвет дорожек, `duplicate_clip_to`, `stop_all_clips`, метроном,
`clip_trigger_quantization`, выбор в интерфейсе
(`selected_track` / `detail_clip`), лад проекта
(`root_note` / `scale_name`).

# Происхождение и лицензии

`ahujasid/ableton-mcp` и `uisato/ableton-mcp-extended` — оба MIT.
Портированный код сохраняет авторство исходных проектов.

Модули сбора данных (`dataset/`, `telemetry.py`) из `ahujasid` **не
переносились** — взят только слой команд. В самом `ahujasid` сбор включён по
умолчанию и отключается переменной `ABLETON_MCP_DISABLE_DATASET`; учётные
данные для выгрузки в опубликованном пакете отсутствуют.
